# Review and repair

Review the user's supplied result against the actual brief and reference roles. A source's performance claim does not prove the user's render meets it. Ask for a missing result only when actual diagnosis depends on it; otherwise label the advice as a prospective prompt improvement.

## Before generation

- Confirm that settings fit the named model. Full-model announcement limits are not Flash limits or proof of access.
- Count references across the combined cap and per-type caps. For editing, include the primary clip in the duration total. Resolve UI accounting ambiguity before submitting a near-limit bundle.
- Check that every active reference has a role and that no dimension has competing owners.
- Check subject count, action direction, ownership of props, ordered keyframe transitions, camera path, and final state.
- Fit beats and speech into the selected duration. Remove redundant description before removing required story events.
- Separate quoted dialogue, scene lettering, subtitles, and audio instructions.

## Inspect the result

Watch the full clip for motion continuity and narrative order. Inspect beginning, action/contact points, shot transitions, and ending frames. Listen for dialogue accuracy, voice identity, synchronization, sound direction, unwanted music, and the ending's audio continuity. Verify duration, resolution, channels, and bit depth from media metadata when making technical delivery claims. HDR also requires appropriate color metadata and interpretation; “10-bit” alone does not establish HDR.

If only stills were inspected, report visual-frame findings only. If audio was not heard, do not claim lip-sync or mix quality was verified. Separate prompt delivery, job submission, generated output, visual inspection, listening, and technical checks.

## Repair the smallest demonstrated failure

| Observed mismatch | Focused revision |
| --- | --- |
| Main subject barely moves | Replace vague low-intensity language with a visible action, path, amplitude, and endpoint; retain a locked camera if requested |
| Identity comes from the wrong reference | Assign identity and motion to different named references; exclude reference-performer appearance |
| Extra subjects appear | State how many distinct subjects are present; explain that several views depict the same entity |
| Action teleports or skips contact | Add approach, contact, reaction, and recovery; simplify only the competing beats |
| Camera breaks the requested axis | Specify its side of the action, travel direction, target, and end framing |
| Keyframes become unrelated shots | Specify whether bridges are continuous movement or cuts; resolve incompatible poses and positions |
| Final beat is missing | Reserve an ending hold, reduce earlier workload, or split into valid clips without changing the requested outcome |
| Voices or lines swap | Tie each line and voice reference to a named speaker; separate turns and listening behavior |
| Speech is rushed | Reduce optional action or extend within the chosen model's limits; do not silently rewrite exact required dialogue |
| Unwanted score appears | State the allowed sound layers and explicitly request no music |
| Label or UI copy changes | Shorten nonessential copy, lock the display surface, improve reading time, and inspect exact characters |
| Targeted edit alters accepted content | Name the edit interval/target and preserve the specific successful portions; reuse the source as primary |
| Continuation restarts the action | Describe the source's final pose, motion, camera, and sound, then only the new action |

Do not assert a hidden cause such as model sampling, CFG, or seed behavior without evidence. Make one coherent revision directed at the mismatch. When further generations are authorized, compare against the same brief; do not launch an indefinite retry loop or call a rewritten prompt a verified repair.
